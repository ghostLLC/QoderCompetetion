## 1. 产品定义

- 名称：斗图军火库（MemeArsenal）
- 一句话：上传一张照片，3 分钟造出一整套原创表情包——照片全程不出浏览器。
- 口号：别偷图了，造你自己的。
- 目标用户：大学生与年轻人群，班级群、宿舍群、社团群的斗图玩家。
- 真实痛点：网络表情包千篇一律且不合场景；不会 PS；现有工具只能做单张，没有"整套"概念；上传照片到云端有隐私顾虑。
- 差异化：本地一键抠图 + 情绪主题整套生成（8–12 张）+ ZIP 导出 + 零注册零上传。

## 2. 范围

### In scope（MVP 完整版）

1. 首页：价值主张、内置示例一键体验、隐私说明、Qoder 制作说明入口。
2. 上传：拖拽 / 文件选择 / 移动端相机；大图压缩与 EXIF 方向矫正；格式与大小校验。
3. 本地抠图：量化分割模型，WebGPU 优先、WASM 兜底；下载与推理进度；可取消/跳过；失败降级相框模式。
4. 编辑台：画布、背景、文字模板、自定义文字、矢量贴纸、照片变换与轻滤镜、图层操作、撤销重做。
5. 整套生成：6 个情绪主题 × 每主题 10 条原创文案；九宫格预览；单格换文案。
6. 导出：1080×1080 PNG 单张（透明底/背景可切）；整套 ZIP。
7. 会话恢复：照片与编辑状态存本机 IndexedDB，刷新可恢复。
8. 响应式：移动端优先，桌面端可用；键盘可达与预设排版替代方案。
9. 文档：build-log（Qoder 使用记录）、论坛帖草稿、README。

### Out of scope

账号体系、云端存储、分享短链、AI 文案生成、多人协作、付费功能、PWA 离线安装、UGC 模板市场。

## 3. 核心流程

1. 打开首页 → 点「拿示例玩玩」或「上传照片」。
2. 自动抠图（进度可见，可跳过）→ 进入编辑台。
3. 选模板、改文案、拖拽贴纸/文字排版。
4. 选情绪主题 → 一键生成整套九宫格 → 单格可换文案。
5. 导出单张 PNG 或整套 ZIP。

## 4. 功能规格

### 4.1 上传

- 支持 jpeg/png/webp；单文件 ≤ 20MB；非图片给出错误提示。
- `createImageBitmap(file, { imageOrientation: 'from-image' })` 解码，最长边压到 1600px 供编辑使用。
- 移动端文件输入带 `capture` 可选相机；桌面端支持拖拽上传。

### 4.2 抠图

- 首选 `@imgly/background-removal`，模型与 onnxruntime-web WASM 全部自托管于站点同源资产目录，懒加载并用 Cache Storage 缓存。
- 兜底实现：若该包自托管受限，改用 `onnxruntime-web` 直连量化 ISNet/U2Net 类模型，自实现预处理与蒙版后处理。
- 推理输入最长边 1024px；蒙版上采样至编辑分辨率，边缘 1–2px 羽化。
- UI：模型下载进度（百分比）→ 推理中动画；提供「跳过抠图」。
- 失败：提示重试，并提供「不抠图继续」（相框模式：圆角/描边相框）。
- 隐私：任何图片数据不发起网络请求；模型仅同源拉取。

### 4.3 编辑台

- 画布：1080×1080 设计稿；屏幕按容器等比缩放显示；导出固定 1080×1080。
- 背景：透明 / 纯色 / 渐变 / 图案（半调网点、斜纹、光晕、纸质）。
- 文字模板（6 套，定义背景+字体+字号+颜色+描边+位置+装饰）：
  1. 经典梗图（得意黑粗体，白字黑描边，顶部/底部）
  2. 荧光弹幕（荧光黄绿条，黑字，微倾斜）
  3. 警告条（黑黄斜纹底，大号黑字）
  4. 漫画气泡（白底黑边气泡，手写感字体）
  5. 手账拼贴（纸质肌理 + 胶带装饰，圆体）
  6. 少女心事（粉紫渐变 + 圆体 + 爱心点缀）
- 元素类型：照片（拖拽/缩放/旋转/水平翻转/滤镜：亮度、对比度、饱和度、黑白）、文字（内容/预设位置/字体/字号 12–96/颜色/描边/对齐/变换）、贴纸（内置 20–24 个矢量 SVG，可变换，部分可改色）。
- 交互：单击选中，拖拽移动，角点缩放，旋转手柄；Delete 删除；复制按钮；上移/下移图层；撤销/重做 ≥ 50 步（Ctrl/Cmd+Z、Shift+Z）。
- 自动排版：文字超出文本框时自动降字号，中文按字符换行，最多 2 行；提供「顶部/底部/居中」一键预设位，作为拖拽的无障碍替代。
- 字体：得意黑（Smiley Sans，OFL）+ 思源黑体子集；导出前等待 `document.fonts.ready`。

### 4.4 整套生成

- 主题（6）：宿舍生存、班级群日常、打工人、无语合集、求求了、吃喝玩乐。
- 每主题 10 条原创文案，附推荐文字模板；生成时套用当前照片与主题模板，自动排版。
- 九宫格预览，每格「换文案」循环切换同主题文案。
- 无照片时先用示例图生成，提示可换图。

### 4.5 导出

- 单张：PNG 1080×1080；背景透明或选用当前背景。
- 整套：ZIP（JSZip），文件名 `斗图军火库_{主题}_{序号}.png` + `使用说明.txt`（应用名与链接）。
- 导出前校验字体加载完成；导出中显示进度。

### 4.6 会话恢复

- IndexedDB 保存：原图 blob、抠图结果 blob、编辑状态（元素列表、模板、主题）。自动保存节流 1s。
- 首页提供「继续上次创作」。

## 5. 视觉规范

- 调性：军火库/装备库，玩梗但不脏乱；UI 干净让作品当主角。
- 色板：警报黄 `#E8FF00`、墨黑 `#111111`、纸白 `#F7F5EF`、警示红 `#FF3B30`（少量强调）。
- 元素：粗描边（2–3px）、半调网点、贴纸裁切白边、硬阴影。
- 字体：标题得意黑，正文思源黑体（系统字体兜底）。
- 动效：贴纸弹入、按钮按压反馈；尊重 `prefers-reduced-motion`。

## 6. 技术架构

- React 19 + TypeScript + Vite + Tailwind CSS；状态管理 Zustand。
- 画布：react-konva；导出时离屏重绘，保证 1080 输出与字体一致。
- 抠图：见 4.2；模型懒加载，不阻塞首屏。
- 打包部署：静态构建 → Qoder Sites（公网链接）。
- 站点结构（前端路由，3 个视图）：
  - `/` 首页
  - `/create` 创建流程（上传 → 抠图 → 编辑）
  - `/packs` 整套生成与导出
  - 页脚「关于」弹层：隐私说明 + Qoder 制作说明
- 目录：`apps/meme-factory/`。

### 6.1 性能预算

- 首屏 JS ≤ 1MB gzip；字体子集 ≤ 2MB；模型按需 ≤ 20MB。
- 首页 LCP < 2.0s（4G，不含模型）。
- 编辑拖拽在中端手机 60fps（图片 ≤1600px）。

### 6.2 已知风险与对策

| 风险 | 对策 |
| --- | --- |
| Qoder Sites 体积/请求头限制未知 | 实现第一周先部署最小版本验证；模型资产分包懒加载 |
| onnxruntime 多线程需 COOP/COEP | 不依赖多线程，单线程 WASM 兜底；有 WebGPU 则优先 |
| 手机推理慢/内存紧 | 输入降采样 1024；任务完成释放张量；进度与取消 |
| 中文字体导致导出错位 | 导出前等待 fonts.ready；字体本地托管 |
| 示例图版权 | 使用生成式合成图或明确授权素材 |
| 评委在国内网络 | 不依赖 Google Fonts/国外 CDN，全部同源资产 |

## 7. 内容资产

- 文案库：60 条原创/改写梗文案，按主题组织，避免整句搬运网络流行语。
- 贴纸：20–24 个自绘 SVG（心、火、汗滴、问号、感叹号、星星、闪光、眼泪、箭头、爆炸框等）。
- 示例图：2–3 张合成人像/宠物图，用于零摩擦体验。
- 模板缩略图自动生成，不单独维护图片资产。

## 8. 错误处理

- 模型加载失败/超时（>60s）：提示 + 重试 + 跳过。
- 图片解码失败：提示更换图片。
- ZIP 导出失败：回退为逐张下载。
- IndexedDB 不可用：降级为不保存会话，功能不受影响。
- 低内存/崩溃：刷新后可恢复最近一次自动保存。

## 9. 测试策略

- 单元测试（Vitest）：文案库完整性（6×10、无重复、长度限制）、自动字号适配算法、文件名清洗、ZIP 清单组装、撤销栈 reducer。
- 组件测试（React Testing Library）：编辑器状态流转（选中/删除/撤销）、整套换文案。
- 手工 E2E（Chrome DevTools MCP）：桌面与 375×812 手机视口走通金路径；模拟模型加载失败走降级路径；检查网络面板无图片上传；下载 ZIP 校验内容与尺寸。
- 视觉 QA：首页、编辑台、整套页截图留档 `docs/assets/`。

## 10. 验收标准

1. 公网链接手机/桌面均可打开，无需登录，首页示例可一键体验。
2. 上传→抠图（或跳过）→编辑→整套→导出全流程可完成。
3. 六个主题各 ≥8 张可导出，PNG 1080×1080、文字渲染正确（无字体错位）。
4. 模型失败时降级模式仍可完成编辑与导出。
5. 网络面板确认图片数据从未上传。
6. 移动端视口核心流程可用，无横向滚动。
7. `docs/forum-post.md` 覆盖赛事要求的 5 个部分；`docs/build-log.md` 记录开发过程。
